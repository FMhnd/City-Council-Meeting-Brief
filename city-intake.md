# City intake and reusable profile

Use this reference when tailoring the skill to a new municipality or filling gaps in a saved profile. It is an intake guide, not a form the user must complete in full. Extract what is already known; ask for the rest only when it affects the requested briefing.

## First-use questions

Suggested wording, shortened to the actual gaps:

> Which city or town and state is this for, which council or committee, and which meeting date (or the next meeting)? Who will read the briefing, and are there particular topics, neighborhoods, or decisions to prioritize? Share an agenda link or packet if you have one; otherwise I can look for public materials. Any preferred length, language, format, or delivery deadline?

If useful, ask one targeted follow-up about the baseline for comparison, an internal spending threshold, or required output template. Do not ask users to find details that are publicly discoverable.

| Information | Ask the user when | Otherwise |
|---|---|---|
| Municipality, state, and jurisdiction | Missing or ambiguous, including duplicate place names or a city versus county distinction | Reuse explicit context; confirm against the official source |
| Governing body and session | More than one plausible council, committee, board, workshop, or special meeting | Use the clearly identified body/session |
| Meeting date or selection rule | Neither an exact meeting nor a rule such as “next regular council meeting” is supplied | Resolve “next” from the current official calendar in the municipality's time zone |
| Audience and purpose | Not already established and likely to change emphasis | Offer a neutral general-audience brief as the default |
| Priority topics or geography | A focus is desired but undefined | Screen all substantive items; ask before narrowing the brief to a subset |
| Source links or files | Public sources are inaccessible, incomplete, or the user wants internal material included | Discover the official municipal site and follow its links to meeting materials |
| Comparison baseline | Several plausible versions exist or a specific historical comparison is intended | Use a clearly identified previous version for a revision comparison; otherwise disclose no baseline |
| Fiscal materiality threshold | The user's organization has an internal threshold or requests threshold-based filtering | Explain documented scale without inventing a universal dollar cutoff |
| Output length, language, format, deadline | A workflow or audience needs a particular deliverable | Approximately two pages plus source references, English, in the conversation |
| Profile and output location | Repeat use is intended and no established project destination is available | Provide the profile in the response until a location is known |

## Discover and verify locally

The following are research fields, not mandatory user questions:

- Official municipality and body names, government structure insofar as it affects the requested decisions, and the clerk/agenda/calendar URLs.
- Actual meeting publishing provider or simple website/PDF arrangement; official links establish the provider's authority.
- Local time zone, regular versus special sessions, and current meeting location or remote-access instructions.
- Local terms for consent items, readings, referrals, hearings, and final action. Find the relevant official procedural source only where needed for interpretation.
- Current comment registration and submission instructions, including session-specific exceptions.
- Fiscal-year dates and the meaning of financial columns when needed to interpret an item; never assume all cities share a fiscal year.
- Locations of addenda, staff reports, fiscal notes, minutes, and vote/action records; distinguish missing, unpublished, inaccessible, and not applicable.

If a rule cannot be verified and is consequential, report that uncertainty or ask for the relevant source. Do not generalize from a neighboring jurisdiction. Information from a saved profile may be stale; record its last verification date and refresh meeting-specific facts.

## Reusable profile fields

Store only fields useful to subsequent briefings. Leave unknown values explicitly unknown, and distinguish user preferences from verified official facts.

| Group | Fields |
|---|---|
| Identity | Municipality; state; jurisdiction type; official body name; session types in scope |
| Official sources | Municipal homepage; body/calendar/agenda URLs; supporting-document and outcome-record locations; access limitations |
| Local interpretation | Time zone; relevant procedural terminology and source links; fiscal-year convention if needed; verification dates |
| User preferences | Audience; purpose; topic/geographic priorities; language; length; format; supplied materiality criteria |
| Reuse | Profile location; output destination; last brief and packet baseline; source/version dates; last verification cutoff |

Keep transient meeting facts in the current brief or run record rather than treating them as permanent profile facts. Do not store unnecessary personal information or credentials. For multiple bodies within one city, share the municipal identity and retain separate calendars, procedures, and baselines.
